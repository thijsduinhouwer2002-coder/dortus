Confluence Cloud storage is full? How to find what takes up space

Confluence Cloud Free and Standard have a storage limit. When you reach it, Atlassian asks you to upgrade or delete content. Here is where to see how much you use, what takes up storage, and how to clean up with what Confluence gives you, with the catch for each step.

Written on 14 October 2026 from the Atlassian pages and tickets linked next to each step. Atlassian changes its pages and menu names now and then, so if your site looks different, go by the linked Atlassian page.

1. See how much storage you use, and your plan's limit

You need admin rights to see storage: Atlassian's Confluence help names Confluence admins, its administration help names site admins. Go to admin.atlassian.com, select your organization if you have more than one, and open your site. With the original user management you select the site's name and URL in the left navigation; with centralized user management you select Apps, then the site. Under Site settings, select Storage. For each app on the site you see the storage used and, unless the plan is unlimited, the storage remaining. The figures are updated only every 4 hours, so a cleanup can take up to 4 hours to show up (Atlassian: Manage your storage usage, Track storage and move data across apps).

Confluence and Jira each have their own storage, and how much an app gets depends on its plan. For Confluence Cloud:

PlanStorage, as listed by Atlassian
Free2 GB
Standard250 GB
PremiumUnlimited
EnterpriseUnlimited

Premium and Enterprise have unlimited storage "regardless of your user tier". Currently, the only way to get more storage is to upgrade the plan (Atlassian: Manage your storage usage, Atlassian Cloud Licensing, Track storage and move data across apps).

When Confluence reaches its limit, you have to upgrade or delete content. Atlassian does not remove your data, but if nothing changes within the time it gives you, your team can no longer edit or create spaces, pages, whiteboards and other content (Atlassian: Manage your storage usage, Track storage and move data across apps).

The Storage page shows one total per app. To see where it goes:

  • Storage per space. The space report shows which space is the big one. In Confluence, select the gear icon at the top right, then Data management, Space reports, Create report and Download. The CSV has a Storage used (MB) column and the number of attachments for every space. App, organization and site admins can create it (Atlassian: Download a spaces report). Atlassian's knowledge base lists the report for Standard, Premium and Enterprise, while Atlassian's tracker says it was released for all plans; on Free, check whether the menu is there (Atlassian: How to identify storage size in Confluence Cloud using the Space Reports feature, CONFCLOUD-73839).
  • Attachment size per page. A Python script in Atlassian's knowledge base adds up attachment sizes per space and per page through the REST API. It skips content the account running it can't see (Atlassian: Finding storage usage of Confluence space and page using REST API).

2. What takes up storage

All pages, live docs, attachments, files and comments take up storage. Start with the biggest attachments and files (Atlassian: Manage your storage usage, Track storage and move data across apps). Three things keep files stored longer than people expect:

  • Attachments nobody shows any more. Removing an image or file from the page in the editor does not delete the attached file. It stays in the page's attachments until someone deletes it there (Atlassian: Display files and images).
  • Old versions of attachments. Confluence keeps a version history for every attachment. Uploading a file with the same name to the same page adds a new version, and the older versions stay (Atlassian: Manage uploaded files). Each old version is kept until you delete it; how much the old versions add to your storage total is not documented.
  • The trash. A deleted page or file goes to the trash of its space, and the attachments of deleted items stay stored until the trash is purged. Confluence Cloud does not empty a space's trash on its own: a deleted item can be restored "until or unless it is manually purged from the trash" (Atlassian: Delete, restore, or purge a content item, Manage uploaded files). Automatic purging is an open request on Atlassian's tracker (CONFCLOUD-18160).

Archiving does not help. Archiving content with attachments frees no storage, because "Confluence keeps files to make historical data available to you". To free storage, delete the attachments or the content itself (Atlassian: Manage your storage usage).

3. Find and delete files in a space

Every space has a list of all its files. Go to the space, select More actions (the three dots) next to the space name in the sidebar, then Space settings, and choose Attachments under Content (Atlassian: Manage uploaded files). The list shows each file and the page or blog post it is attached to (Atlassian: How to search and view space attachments). To see which spaces and pages hold the most, use the space report and the script from step 1.

To delete a file, open the page it is attached to, select Show details in the toolbar at the bottom right, then Attachments, and delete the file there. That needs the Delete Attachment space permission. Deleting a file removes all its versions, and the file goes to the space trash, where it stays stored until the trash is purged (Atlassian: Manage uploaded files, Insert the attachments macro).

  • The catch. The list tells you where a file is attached, not whether any page still shows or links it. Confluence Cloud has no built-in way to find unused attachments; a way to detect them is an open request on Atlassian's tracker (CONFCLOUD-16577). A file attached to one page can also be shown or linked on another page, so checking the page it is attached to is not enough (Atlassian: Insert the attachments macro). If you are not sure, download a copy before you delete it; until the trash is purged, a space admin can restore it.
  • One at a time. The Confluence interface has no option to bulk delete files, or to delete all files on a page at once (Atlassian: Manage uploaded files; open request CONFCLOUD-17020). For a REST API script, see the short answers below.

4. Delete old versions of a file

Open the page, select Show details, then Attachments, and select the arrow to the left of the file name. All available versions of the file appear below it. Select Delete next to a version and confirm (Atlassian: Manage uploaded files).

  • Check the gain. How much old versions add to your storage total is not documented. Delete a few, check the Storage page after 4 hours, and then decide whether to go on.
  • Space admins only. Deleting one version needs the Space Administrator permission on top of Delete Attachment. In a space where you are not a space admin, ask one of its space admins.
  • No undo. A deleted version can't be restored. A space admin can restore a whole deleted file from the trash, but not a single version. Download the version first if you might need it.
  • By hand. You delete versions one by one. Confluence Data Center can remove old versions automatically with retention rules; they are not available in Cloud (Atlassian: Differences administering Confluence Data Center and Cloud).

5. Empty the trash

In the space, open Space settings, then Trash under Content. Purge removes one item, Purge All empties the trash of that space. Purging is permanent: the item, all its versions and its attachments are gone and can't be restored. Atlassian advises checking first that the attachments on trashed items are not used on other pages, and moving them to another page if you are not sure (Atlassian: Delete, restore, or purge a content item). Confluence can't show you where a file is used (see step 3), so when in doubt, restore the item or download its attachments before you purge.

  • Per space. Each space has its own trash, and space admins empty it. A site with many spaces means many trashes; in a space where you are not a space admin, ask one of its space admins.
  • Large trashes. The Trash view shows at most 500 items. Items beyond that can only be reached through the REST API, which this guide does not cover. This is an open bug on Atlassian's tracker (CONFCLOUD-83600).
  • Deleted spaces are separate. A whole space in the trash is managed in Confluence administration under Trashed spaces. Since 6 January 2025, Atlassian permanently deletes spaces that have been in the trash for at least 60 days (Atlassian: Delete a space).

After a cleanup, give the Storage page in admin.atlassian.com up to 4 hours before you check the new total.

Short answers

How much storage does Confluence Cloud Free include? 2 GB. Standard has 250 GB; Premium and Enterprise are unlimited (Atlassian: Manage your storage usage, Atlassian Cloud Licensing).

Does archiving pages free up storage? No. Delete the attachments or the content to free space.

Does deleting a page free up storage straight away? No. Its attachments stay stored until the space trash is purged, and the Storage page updates only every 4 hours.

Can I bulk delete attachments in Confluence Cloud? Not in the Confluence interface: there you delete files and old versions one at a time. A REST API script in Atlassian's knowledge base deletes all attachments on one page uploaded before a date you choose, with all their versions; Atlassian recommends backing up the space first (Atlassian: How to delete attachments filtered by date from a Confluence Cloud page using the REST API).
