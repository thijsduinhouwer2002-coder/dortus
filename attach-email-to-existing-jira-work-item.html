How to add an email to an existing Jira work item

The work item already exists. Now a customer, a supplier or a colleague sends an email that belongs on it. You want the email on that work item, not a new ticket. There are three ways, and they keep different parts of the email.

Way 1: save the email as a file and drop it on the work item (free)

This keeps the whole email, headers and attachments included. First save it as a file.

  • New Outlook: open the message, then choose More actions, Save as. Microsoft says it "will be saved as an .eml file", usually in your Downloads folder (Microsoft).
  • Classic Outlook: open the message, choose File, Save As, pick a folder and save (Microsoft). Which format you get, and what it keeps, is on Outlook .msg vs .eml.
  • Gmail: open the email, click More, then Download message. You get an .eml file (Google).
  • Apple Mail: select the email, choose File, Save As, and set the format to Raw Message Source (Atlassian KB).

Then drag the file onto the work item. Dragging a message straight from the new Outlook into Jira does nothing: no upload, no error. Atlassian closed that bug report as Invalid. Its workaround is to drag the email to your desktop or a folder first, then drag that file into Jira (Atlassian: JRACLOUD-94217).

Way 2: Atlassian's apps for Outlook and Gmail

Jira Cloud for Outlook is published by Atlassian. From your inbox you can create a work item from an email, or update one: "transition, assign, and comment" (Microsoft Marketplace). Emails attached with the add-in show in an Attached emails section in the Jira web view. The mobile app does not show that section; adding it is an open suggestion (Atlassian: API-637).

Gmail: Atlassian's Jira app for Gmail lets you "link the email to the Jira work item as a comment" (Atlassian blog).

Both work from one person's inbox, so everyone who files emails needs the app.

Way 3: forward or reply with the work item key in the subject

This only works if your project receives email.

Jira's own mail handler. Atlassian: "If the subject contains a work item key, the message is added as a comment to that work item." Attachments on the email become attachments on the work item. The limit is 25 MB per email. Jira does not process HTML or rich text formatting correctly, and the comment handlers convert the body to plain text. Jira accepts these emails from licensed users (Atlassian). Setup is on Create Jira work items from email.

Jira Service Management. Jira first looks for a work item key in the subject. If there is none, it compares the Message-ID, In-Reply-To and References headers with earlier emails. Even with a match, the sender must be allowed to comment: the reporter, a request participant or a member of the shared customer organization. Otherwise Jira creates a new request. An admin can switch on "Allow all emails that contain a valid issue key to be added as a comment to the issue?" (Atlassian KB).

What you lose: the comment is the text of your forward, not the email. A forward is a new email, so the original email's full headers are not in it. Forwarding the email as an attachment keeps the original, but it can arrive as a file without an extension. Atlassian tracks this for Outlook forwards (JRACLOUD-40477, open since 2014) and for attached .eml files with special characters in the name (JSDCLOUD-19284, July 2026). See also the original email behind a JSM request.

Why the attached email then shows as code

Ways 1 and 3 leave an email file on the work item. Jira Cloud has no viewer for it. Atlassian's own tracker says .eml files are rendered as text and .msg files as code (Atlassian: JRACLOUD-77500, open since October 2021). Every reader has to download the file and open it in a mail app. A Marketplace app can show the email on the work item instead. All the ways to read it are on How to open .msg and .eml attachments in Jira.

Full disclosure: Dortus makes such an app. MailView shows .msg and .eml attachments on the work item with formatting, inline images and the files inside. That includes forwarded emails attached without a file name. It stores nothing and sends nothing anywhere, and works in Jira and the agent view of Jira Service Management. It is on the Atlassian Marketplace.

Short answers

Can I forward an email to Jira without creating a new ticket? Yes, if your project receives email and the subject contains the work item key. In Jira Service Management the sender must also be allowed to comment on that request.

Why can't I drag an email from the new Outlook into Jira? The drop does nothing. Drag the email to your desktop first, or use More actions, Save as, then drag the file into Jira.

Which way keeps the most of the email? The saved .eml or .msg file. A comment holds the text; the file holds the whole message.
