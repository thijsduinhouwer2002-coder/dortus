Migrating Questions for Confluence to Cloud: when questions are missing

Atlassian's Confluence Cloud Migration Assistant migrates Questions for Confluence along with your spaces, and Questions for Confluence is available on Cloud. For most teams that is all they need. This page is for when the migration did not go as planned: what has to be in place, what does not come along, the known issues, and your options when questions are missing.

The normal route: the migration assistant

Atlassian's migration knowledge base says the Questions for Confluence app can be migrated with the Confluence Cloud Migration Assistant, CCMA for short (Atlassian: Migrating Questions for Confluence App). The request for this on Atlassian's tracker, MIG-106 "Support the Migration of Questions for Confluence", was created on 27 December 2019 and closed with the resolution Done on 1 November 2021 (Atlassian: MIG-106).

So if Questions for Confluence works for your team, migrate it with the assistant and keep using it on Cloud. There is no reason to change apps for the migration.

What has to be in place

The migration article lists what has to be in place. Check these before you migrate, and again first if something went wrong:

  • The app is installed on Data Center. Atlassian's pre-migration checklist has a check for Questions for Confluence in your Support Zip, under the step about Marketplace apps (Atlassian: Confluence pre-migration checklist).
  • The app is installed on Cloud before the migration. The article says Questions for Confluence has to be installed on your Cloud site first: "if the app was already installed in the past, we recommend re-installing the app". That registers the site to receive the migration events. Atlassian's Cloud documentation explains how to install Questions for Confluence.
  • Users and spaces go through the assistant too. The article says: "If users or spaces were not migrated through CCMA then app migration will not work properly." Migrate with all users and groups and the spaces; otherwise only part of the questions comes along.
  • People have permissions on Cloud. The app creates the questions and answers on behalf of the people who wrote them, so according to the article those people "should have permissions on the cloud side too". The article adds that this also covers comments and attachments in the CQ space.

What does not come along

  • Drafts. The article says: "Drafts are not supported on cloud, thus not migrated."

Known issues

  • Questions or answers that do not show. CONFCLOUD-77079, "Migrating Questions for Confluence sets the wrong plugin key". According to the migration article, the affected questions and answers then do not show. Atlassian closed the ticket on 13 May 2025 with the resolution Timed out, not as fixed, so whether it still happens is not known. Installing or reinstalling the app on Cloud before the migration, as above, is what the migration article asks for.
  • Dates reset to the migration date (fixed). CONFCLOUD-76360, "Migrating Questions for Confluence resets the Timestamps", was a known issue. The migration article still lists it with "No workaround is available", but the ticket was marked Fixed on 16 October 2024.

When questions are missing after the migration

  • Go through the list above. Most of the conditions are about the order of things: the app on Cloud first, users and spaces through the assistant, permissions in place.
  • Questions missing because of permissions. The migration article describes a second run: fix the permissions first, create a dummy space, start a new migration with all users and groups, and include only the Questions for Confluence app. See the article for the exact steps.
  • Contact Atlassian Support with the details of your migration if that does not explain it.
  • Know that a second try is hard. The article says re-migrating after a partial migration is difficult, because there is no export or import tool for Questions in Cloud: that feature request "has not been implemented on the cloud yet". The request is CONFCLOUD-51723, "Exporter / Importer for Confluence Questions (Cloud)": created in October 2013, with the status Future Consideration and 140 votes on 14 October 2026.
  • Keep a copy while the old site still runs. Questions for Confluence 2.3.0 and later on Server and Data Center has a REST API. Atlassian's export article uses GET /rest/questions/1.0/question?limit=700 for the questions; the answers are fetched one by one with /rest/questions/1.0/answer/{answerId} (Atlassian: How to export Confluence Questions data). The REST reference lists limit as required and start for the next page (Atlassian: Confluence Questions REST API). Even if you never import it, that file is your archive.
  • Recreate the ones that matter. For a few dozen questions, asking them again in Questions for Confluence on Cloud, with their best answer, is often quickest. They get today's date and the name of whoever posts them.

AskSpace as one of the options

Full disclosure: I build AskSpace at Dortus. AskSpace is a Q&A app per Confluence space. It is mainly an option if you are already on Cloud and the questions stayed behind, or if you want to keep the questions without Questions for Confluence. It can import the JSON file from the Questions REST API on your old Confluence. What that import does:

  • What comes in. Each question's title and text, the author's name, the date, up to 3 topics as tags, and, when the file contains them, the answers with their author and date. The accepted answer becomes the best answer.
  • Answers only when they are in the file. If the file lists answers by ID without their text, AskSpace imports the questions only and says the answers are missing, with the call to fetch them.
  • What does not come in. Votes and comments. Author names arrive as text, not linked to Cloud accounts. Paragraphs, lists, links, bold and code stay; images and attachments become the line [image omitted]; other formatting is dropped.
  • A preview first, an undo afterwards. A space admin starts the import from the AskSpace settings of a space. Before anything is saved, the preview shows how many questions it found, the first five, and what it left out or changed: a question without a title, a repeated question, an answer without text, a date it could not read (that question gets today's date). Afterwards, Undo this import removes the imported questions again. Nothing changes on your old Confluence.
  • Limits. AskSpace imports up to 100 answers per question and up to 3 tags per question, and up to 5,000 questions per import and 6,000 per space. Answers after the 100th are left out, also when one of them is the accepted answer.
  • The file format. Atlassian does not document the format of this file in detail. AskSpace reads the field names it knows; a field it does not find stays empty.

Whether AskSpace or Questions for Confluence on Cloud fits your team better is a separate question: see Questions for Confluence vs AskSpace. AskSpace is listed on the Atlassian Marketplace, and Getting started with AskSpace has the setup.

Which route fits

  • You are still on Data Center. Include Questions for Confluence in the migration and check the list above first. That keeps the questions in the app your people know.
  • You migrated and questions are missing. Go through the list above, try the second run if it is about permissions, and contact Atlassian Support.
  • You are on Cloud, the questions stayed behind, and the old site still runs. Export the file. Then recreate the questions that matter, or import the file into an app that reads it.
  • Whatever you choose, keep the export file from Data Center as an archive before you switch the old site off.
