Migrating Questions for Confluence from Data Center to Cloud

Questions for Confluence exists for Data Center and for Cloud, and Atlassian's Confluence Cloud Migration Assistant can move its questions and answers. It works best when you plan for it before the migration. This page sets out what Atlassian says has to be in place, what does not come along, and what you can do if the questions were left behind.

The short answer

Yes, the migration assistant can move them. Atlassian's migration knowledge base says the Questions for Confluence app can be migrated with the Confluence Cloud Migration Assistant (CCMA) (Atlassian: Migrating Questions for Confluence App). The feature request for this on Atlassian's tracker, MIG-106 "Support the Migration of Questions for Confluence", is closed with the resolution Done, and the ticket gives 1 November 2021 as the date it was resolved (Atlassian: MIG-106).

You may also find an older Atlassian page that says the opposite. The Server-to-Cloud guide in the documentation for Confluence 7.1 says that Atlassian's own apps, such as Team Calendars for Confluence and Questions for Confluence, are not included in the migration (Atlassian: Migrate from Confluence Server to Cloud). That page belongs to an older release; the migration article above is the current one to follow.

Before you migrate

The migration article lists what has to be in place. In short:

  • Check that the app is installed on Data Center. Atlassian's pre-migration checklist has a check for Questions for Confluence in your Support Zip, under the step about Marketplace apps (Atlassian: Confluence pre-migration checklist).
  • Install the app on Cloud first. The article says Questions for Confluence has to be installed on your Cloud site before the migration, and to reinstall it if it was installed there before. That registers the site to receive the migration events. Atlassian's Cloud documentation explains how to install Questions for Confluence.
  • Move users and spaces with the assistant. According to the article, the app only migrates correctly if the users and spaces were migrated through CCMA as well.
  • Permissions on Cloud. The app creates the questions and answers on behalf of the people who wrote them, so those people need matching permissions on the Cloud site.

Limits of the migration

  • Drafts. The article says drafts are not supported on Cloud, so they are not migrated.
  • An easy second try. If a migration was partial, migrating again is hard, the article says, because there is no export or import tool for Questions in Cloud. An exporter and importer for Questions in Cloud is a feature request on Atlassian's tracker (CONFCLOUD-51723).

For questions that went missing because of permissions, the article describes a second run: fix the permissions, create a dummy space, start a new migration with the users and groups, and include only the Questions app. See the article for the exact steps.

Known issues to check

The article lists known issues with their tickets. Open the tickets to see their current status before you migrate:

  • Questions or answers that do not show. During the import, the app's plugin key can be set wrongly, and those questions and answers then do not appear (CONFCLOUD-77079). This is why the article asks you to install or reinstall the app on Cloud first.
  • Dates reset to the migration date. The dates of questions and answers can be reset to the day of the migration (CONFCLOUD-76360).

If the questions were left behind

Say your spaces are already in Cloud, moved without the questions, or the migration route above does not fit. These are the options, roughly from least to most effort:

  • Ask Atlassian. If you migrated with the assistant and questions are missing, start with the migration article above, and contact Atlassian Support with the details of your migration.
  • Recreate the ones that matter. For a few dozen questions, asking them again in Questions for Confluence on Cloud, with their best answer, is often quickest. They get today's date and the name of whoever posts them.
  • Keep a copy from Data Center. Questions for Confluence 2.3.0 and later on Server and Data Center has a REST API. Atlassian's export article uses GET /rest/questions/1.0/question?limit=700 for the questions; the answers are fetched one by one with /rest/questions/1.0/answer/{answerId} (Atlassian: How to export Confluence Questions data). The REST reference lists limit as required and start for the next page (Atlassian: Confluence Questions REST API). Even if you never import it, that file is your archive.
  • Use an app that imports that file. That is where AskSpace comes in; see below.

AskSpace as one of the options

Full disclosure: I build AskSpace at Dortus. AskSpace is a Q&A app per Confluence space, and it can import the JSON file from the Questions REST API on your old Confluence. What that import does:

  • What comes in. Each question's title and text, the author's name, the date, up to 3 topics as tags, and, when the file contains them, the answers with their author and date. The accepted answer becomes the best answer.
  • Answers only when they are in the file. If the file lists answers by ID without their text, AskSpace imports the questions only and says the answers are missing, with the call to fetch them.
  • What does not come in. Votes and comments. Author names arrive as text, not linked to Cloud accounts. Paragraphs, lists, links, bold and code stay; images and attachments become the line [image omitted]; other formatting is dropped.
  • A preview first, an undo afterwards. A space admin starts the import from the AskSpace settings of a space. Before anything is saved, the preview shows how many questions it found, the first five, and what it left out or changed: a question without a title, a repeated question, an answer without text, a date it could not read (that question gets today's date). Afterwards, Undo this import removes the imported questions again. Nothing changes on your old Confluence.
  • Limits. Up to 5,000 questions per import and 6,000 per space.
  • The file format. Atlassian does not document the format of this file in detail. AskSpace reads the field names it knows; a field it does not find stays empty.

Whether AskSpace or Questions for Confluence on Cloud fits your team better is a separate question: see Questions for Confluence vs AskSpace. AskSpace is listed on the Atlassian Marketplace, and Getting started with AskSpace has the setup.

Which route fits

  • You are about to migrate with the assistant. Include Questions for Confluence and follow Atlassian's steps above. That keeps the questions in the app your people know. If Questions for Confluence works for your team, there is no reason to change apps.
  • The spaces are already in Cloud without the questions. Start with Atlassian Support. For what remains, recreate a handful by hand, or export the file and import it into an app that reads it.
  • Whatever you choose, keep the export file from Data Center as an archive before you switch the old site off.
